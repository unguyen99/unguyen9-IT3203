HTTP 0.9, 1.0, and 1.1

HTTP/0.9

In 1989, Tim Berners-Lee had a proposal about linked documents that can be shared and accessed by people. In 1991, the HTTP/0.9 protocol was released. The first HTTP version was very simple. The HTTP Request header was one line and contained one method, GET. The response only contained the HTML document. Unlike later HTTP versions, the connection was terminated after the request gets sent. The HTTP/0.9 version name only came after more HTTP versions were released. The subsequent HTTP versions are RFC (Request For Comments). As HTTP develops to overcome limitations and introduce more features, more RFCs are introduced with some RFCs becoming obsolete.

HTTP/1.0

In 1996, the release of RFC 1945 defined HTTP/1.0. The HTTP request now contained the HTTP version in the header, status codes, new methods, and caching. HTTP became more versatile as hypermedia can be sent and not just hypertext documents. Status codes are sent by the web server to indicate if the request was successfully completed. Status codes that begin with 2 (2xx) indicates success while 4xx indicates error from the client side. At this point in time HTTP/1.0 was not an official standard. Some method examples are GET, POST, and PUT. Different implementations of HTTP were observed over time and certain implementations were brought to the HTTP/1.0 version. The HTTP protocols were in an experimental phase and different features were being tested.

HTTP/1.1

With continuous development in HTTP versions, HTTP 1.1 was officially standardized in 1997 in RFC 2068. It introduced the keepalive connection, where the connection between the client and server no longer closed after every request. It remained opened, allowing the user to use the same connection to send more requests. Keeping the connection open reduced the repetitive opening of new connections. RFC 2068 included the site name in the header so the same IP address could be used for different sites. Two years later in 1999, RFC 2616 replaced RFC 2068.
